# 电量数字字号／字重的无效区间

## 原因

Find N5 当前布局 `4,3|5,1|7|` 将电量数字放在圆环上部。设置界面此前按整个圆环统一提供 16–56，而上、下部文字的空间远小于中部；超过实际容量后，绘制的安全拟合会抵消继续增加的字号。自适应环线解决了开口间距，但不会扩大组件可用空间。

最初读取 `/system/fonts/SysFont-Regular.ttf` 的 fvar 表，得到 wght 100／400／700；将它当作当前字体的判断有误，`fonts.xml` 自身声明已经不是系统字体来源。后续 `adb shell cmd font dump` 确认当前 sans-serif 映射 `/system/fonts/Roboto-Regular.ttf`，其 fvar wght 为 100／400／900。真机字重滑块确实保留 100–900，不应人为截断到 700。该推断已向维护者更正。

真正需要处理的是拟合与字重耦合：字重提高使文字变宽，重新拟合时反过来缩小字号，抵消了部分加粗效果。新增回归在 1.1.23 复现相同设置字号的 em 从 42.77654 降至 41.134735；不能以“几个字重都能绘制”代替“字重切换时尺寸稳定”。

## 修改

- 圆环数字控件复用生产文字拟合，逐个检查已放置数字的区域、当前字体／字重／线宽，以及 0–100 所有读数，提供第一个安全、连续的有效字号区间。充电时暂时隐藏的候选位置也纳入，不随充电状态跳动。
- 数字拟合先为 900 字重预留空间，再绘制所选字重，避免加粗后反向缩小字号。特殊自定义字体仍以实际字重做一次安全检查，防止细体反而更宽时越界；其他组件的文字拟合不变。
- 保存过大的字号不迁移、不回写；控件显示有效范围，原绘制仍保留安全拟合。移动数字或改变字体、字重、线宽后重新计算范围。胶囊／矩形保留原有样式范围与空间适配。
- 电量字重用 Android Paint 的数字轮廓识别相邻重复结果，按有效设置提供离散档位。比较轮廓而非 advance，避免等宽数字被错误合并；自定义字体的合成加粗也作为不同结果。结果按字体 generation 缓存，设置面板重组不反复探测；切换字体失效重算。
- 不改变已保存字重，不修改原生字体文件。环线继续按最终实际墨迹适配，宿主尺寸不变。

## 检查与待验收

新增五项生产渲染模型回归：上下部字号全区间与全部电量读数、移到中部／移回及保存值不变、无区别字重合并与返回值保护、字体切换与探测缓存、提高字重时 em 稳定。最后一项在旧实现先失败，再验证修复；桌面替身只有 regular／bold，不能代替 Find N5 的真实字重检查。

1.1.23 已完成 211 项 JUnit（release app 58／render 96／host 57）、22 项 Python、Lint、Release 构建、签名集成与 Observer 包装检查。main CI `41277479338`、tag CI `41277479151`、候选 `41277485473`；APK SHA-256 `e5678b48f8dfd3fc08c58746e5db3235998c2bfd239fdd066689376f4b8f74e3`，artifact `13071737436`。覆盖安装回拉一致，安装时全部偏好一致；因该版仅改控件，保留 SystemUI PID 28840。

真机设置页显示上部字号 16–30，原保存值 37 没有被改写。字重通过真实拖动验证 500／900，再恢复 700；初次 tap 没有移动滑块，不计作有效操作。启动设置页会更新 transport 元数据，实际用户设置已恢复一致。500／900 状态栏数字截取的黑色像素分别为 241／265，存在实际绘制差异，不能据此称 900 无效。临时字体工具未安装，已取消并移除临时密钥，不将其作为真机证据。

继续修复的版本为 **1.1.24 / 10124 测试候选，未公开发布**。提高字重的稳定尺寸修复已通过完整门禁：212 项 JUnit（58／97／57）、22 项 Python、Lint 和 Release 构建；云端签名／安装及维护者视觉确认待补齐。当前公开稳定版仍为 1.1.21，1.1.22／1.1.23 均未公开发布，开口和控件修复包含在本次候选中。
