# 电量数字字号／字重的无效区间

## 原因

Find N5 当前布局 `4,3|5,1|7|` 将电量数字放在圆环上部。设置界面此前按整个圆环统一提供 16–56，而上、下部文字的空间远小于中部；超过实际容量后，绘制的安全拟合会抵消继续增加的字号。自适应环线解决了开口间距，但不会扩大组件可用空间。

读取手机 `/system/fonts/SysFont-Regular.ttf` 的 OpenType fvar 表，实际 wght 轴为 100／400／700（最小／默认／最大）。系统 fonts.xml 仍列出 800／900 请求，不能据此认定字体包含这些轮廓。此前字重滑块统一提供 100–900，后两档没有实际区别。

## 修改

- 圆环数字控件复用生产文字拟合，逐个检查已放置数字的区域、当前字体／字重／线宽，以及 0–100 所有读数，提供第一个安全、连续的有效字号区间。充电时暂时隐藏的候选位置也纳入，不随充电状态跳动。
- 保存过大的字号不迁移、不回写；控件显示有效范围，原绘制仍保留安全拟合。移动数字或改变字体、字重、线宽后重新计算范围。胶囊／矩形保留原有样式范围与空间适配。
- 电量字重用 Android Paint 的数字轮廓识别相邻重复结果，按有效设置提供离散档位。比较轮廓而非 advance，避免等宽数字被错误合并；自定义字体的合成加粗也作为不同结果。结果按字体 generation 缓存，设置面板重组不反复探测；切换字体失效重算。
- 不合成不存在的 800／900 字形，不改变已保存字重，不修改原生字体文件。环线和宿主尺寸没有因本次控件修改而变化。

## 检查与待验收

新增四项生产渲染模型回归：上下部字号全区间与全部电量读数、移到中部／移回及保存值不变、无区别字重合并与返回值保护、字体切换与探测缓存。桌面替身只有 regular／bold，不能代替 Find N5 的真实字重检查。

本地完整检查已通过：211 项 JUnit（release app 58／render 96／host 57）、22 项 Python、Lint 与 Release 构建。签名集成与 Observer 包装检查另见同目录本轮日志。临时字体工具安装未完成，已取消，不记作真机轮廓验证；手机 fvar 范围读取属于静态证据。
