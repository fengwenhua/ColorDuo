# 自定义状态栏在下拉／收回时的尺寸跳变

## 现场与原因

Find N5，SystemUI 16.99.12，1.1.17 候选，外屏状态栏 120%。录制两轮下拉／收回并抽帧，确认镜像过渡期间顶部内容偏小，交回真实状态栏后又恢复自定义大小。

JADX MCP 对照 FakeBinder、StatusBarFakeFrame、ClockFakeFrame、NotificationFakeFrame、SystemIconFakeFrame，以及通知／快捷设置的镜像控制器：

- FakeBinder 分别引用真实时钟、通知区域、右侧容器。镜像调用 realView.draw(canvas)，绕过真实控件自身及祖先的 View 缩放矩阵。
- 原模块只缩放真实状态栏外层，因此镜像仍按原始内容大小绘制；镜像尺寸元数据也来自未经缩放的 width／height，Y 坐标计算没有包含外层矩阵。
- 下拉头部属于另一套控件，原来没有同步自定义倍率。桌面恢复一帧之前的小图标与这套交接不一致有关，不能仅靠延后刷新或重新动画解决。

录像、抽帧、原始窗口信息与反编译片段仅保存在忽略目录 `.local/shade-scale-2026-10-29/`。

## 修复

- 定向处理 ColorOS 镜像控件的绘制、尺寸和真实屏幕坐标，补齐原状态栏外层的倍率，保持左右物理锚点及通知间距。
- 镜像测量直接写目标值且只在尺寸变化时请求布局，避免原生 reset 与自定义尺寸来回覆盖。
- 镜像时钟以自定义状态栏尺寸为动画起点，平滑交给面板原有大时钟；保留系统的位移、透明度及原有时间布局动画，不额外叠加放大动画。
- 同步下拉头部的运营商／网络／电量区域，保留原生缩放变化；100% 或关闭总开关时还原矩阵、尺寸和裁剪状态。
- 仅当源控件属于模块已缩放的真实状态栏时，才补齐镜像矩阵；独立锁屏来源不强制套用桌面矩阵。
- 保留 1.1.17 网络类型恢复修复，不改变配置键或既有用户配置。
