# Issues #10 / #11：分析与验证

来源：[网络类型问题 #10](https://github.com/fengwenhua/ColorDuo/issues/10)、[双电芯功率 #11](https://github.com/fengwenhua/ColorDuo/issues/11)。

## #11 双电芯功率

新增全局、默认关闭的「双电芯功率补偿 ×2」，仅用于已知上报单颗电芯电压与电流乘积的设备。不能仅根据“双电芯”自动启用：上报整组电压的电池不应再次乘二。没有一加 15 的实机电学测量，不声称自动识别该设备。

补偿在展示阶段施加一次，ColorOS/HyperOS 各自原始单位换算不变，缓存采样不变；开关后无需等下一次采样。配置通过统一 schema 走首装默认值、偏好、Bundle、JSON、复制和局部更新；预览同步。温度及充满、暂停充电隐藏逻辑不变。

本地 243 项 JUnit 通过，包括新增的默认关闭、连续刷新不累乘、关闭恢复、未知功率不伪造读数、真实零电流、温度不变、充满隐藏，以及跨平台单位隔离测试；现有 schema 矩阵覆盖新字段传输。真机 UI 与最终组合包测试另行记录。

## #10 双卡

代码确认：ColorOS `prepare()` 原先对最近区域要求 `mobileCount == 1`，两个同级移动信号会整体被拒绝；只有一个被系统布局展示的条目时也没有关联默认数据卡。`Plan`、绘制帧和原生接管租约目前仅能表达一个移动信号，不能直接去掉计数检查或仅隐藏第二张卡。

Find N5 当前只有一张 SIM。必须分别验证默认上网卡切换及两卡同时绘制，不能把单卡实机通过记为双卡通过。双卡同时合并需要扩展每卡读数、每卡原生视图租约、绘制和无障碍描述；未覆盖的第二张卡应保留原生显示。
