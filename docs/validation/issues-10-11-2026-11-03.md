# Issues #10 / #11：分析与验证

来源：[网络类型问题 #10](https://github.com/fengwenhua/ColorDuo/issues/10)、[双电芯功率 #11](https://github.com/fengwenhua/ColorDuo/issues/11)。

## #11 双电芯功率

新增全局、默认关闭的「双电芯功率补偿 ×2」，仅用于已知上报单颗电芯电压与电流乘积的设备。不能仅根据“双电芯”自动启用：上报整组电压的电池不应再次乘二。没有一加 15 的实机电学测量，不声称自动识别该设备。

补偿在展示阶段施加一次，ColorOS/HyperOS 各自原始单位换算不变，缓存采样不变；开关后无需等下一次采样。配置通过统一 schema 走首装默认值、偏好、Bundle、JSON、复制和局部更新；预览同步。温度及充满、暂停充电隐藏逻辑不变。

本地 243 项 JUnit 通过，包括新增的默认关闭、连续刷新不累乘、关闭恢复、未知功率不伪造读数、真实零电流、温度不变、充满隐藏，以及跨平台单位隔离测试；现有 schema 矩阵覆盖新字段传输。真机 UI 与最终组合包测试另行记录。

## #10 双卡

代码确认：ColorOS `prepare()` 原先对最近区域要求 `mobileCount == 1`，两个同级移动信号会整体被拒绝；只有一个被系统布局展示的条目时也没有关联默认数据卡。`Plan`、绘制帧和原生接管租约目前仅能表达一个移动信号，不能直接去掉计数检查或仅隐藏第二张卡。

Find N5 当前只有一张 SIM。必须分别验证默认上网卡切换及两卡同时绘制，不能把单卡实机通过记为双卡通过。双卡同时合并需要扩展每卡读数、每卡原生视图租约、绘制和无障碍描述；未覆盖的第二张卡应保留原生显示。

本轮修正默认数据卡选择：订阅源缓存系统提供的 slot 映射，默认数据卡改变时即使 enabled 布尔值不变也刷新。选择器仅在同一最近状态栏区域中选择唯一对应条目，类型和信号共用该条目；默认卡暂缺、重复或未知且多卡时保留原生，不借用另一卡缓存。没有把 subscription ID 当成 slot，也不在绘制时查询 Binder。

抽取生产 `prepare()` 的测试覆盖卡 2、切回卡 1、两卡健康且 enabled 一样、缺失／重复条目、未知默认卡，以及卡 1 为 4G、卡 2 为 5G 时类型和信号共选同卡。完整生产订阅源测试覆盖 subscription 7 映射 slot 1，以及切卡同布尔值刷新、旧回调拒绝、关闭清理。本轮定位为部分改善，不关闭 #10，也不声称双卡已完成实机验收。

组合包本地门禁：247 项 JUnit、release lint 与 release APK 构建通过。其他命令行门禁及同签名真机验收见移动信号验证记录。

## 组合候选真机结果

1.1.30 已同签名覆盖安装 Find N5，安装时配置无变化。新「双电芯功率补偿 ×2」入口、说明和默认关闭状态可见；实际点选后 UI 与偏好均为 true，随后关闭并确认恢复 false，配置传输快照包含新字段。手机此时已插电、100% 且状态为 FULL；两项读数保持隐藏，没有因开启补偿重新冒出。功率 ×2 的计算与反复刷新由生产代码单元测试覆盖，不能将本轮满电真机结果当作一加 15 实测功率验证。

单卡 N5 日志确认默认订阅 1 映射 slot 0，两种样式的网络切换正常。没有第二张卡，默认卡切换和双卡不同制式场景只通过生产源码 fixture 测试，仍待双卡实机反馈；两卡同时合并尚未实现。

已恢复原有用户设置、圆环样式、网络开关及补偿关闭状态。两种样式共 4273 帧网络回归与签名/CI 详情见 [移动信号验证](mobile-flicker-2026-11-03.md)。本轮未向 issue 发送回复、未关闭 issue、未公开发布候选。
