# 兼容性画像与报告

已验证的硬件为 OPPO Find N5（PKH110），ColorOS 16，SystemUI 16.99.12。
相同符号画像的其他设备属于预期兼容；其他 ColorOS 16 设备仍未实测。
关键能力缺失时适配器保留/恢复原生图标，不因“同为 ColorOS 16”就强制接管。
HyperOS 路径继续维护，当前没有第二台 HyperOS 真机，不能将 Find N5 结果算作 HyperOS 通过。

`ColorOsSymbols` 集中保存 93 个生产适配器使用的反射类/方法/字段及资源名称。
画像分别检查电池、网络、供电、时钟的关键符号；实际 Hook 成功状态由对应适配器单独上报，
避免把类存在当作功能安装成功。画像只读，不增加网络/电池采样，也不会隐藏任何 View。

设置页“关于 → 复制兼容性报告”通过指定 SystemUI 包的有序广播查询当前状态。
SystemUI 动态 receiver 要求模块签名权限，API 34+ 另校验共享的发送 UID/包名；
结果回到该次查询的 result receiver，不开放 app 回复入口。
最多等待 3 秒；模块未加载时仍能复制本机版本信息，并明确显示 `no-runtime-report`。

报告只包含固定字段：厂商/型号、Android/固件/SystemUI/模块版本、ROM 选择、能力布尔值与异常类型。
不会读取或输出 SSID、手机号、通知、用户给设备起的名字、异常消息或原始日志。
不会自动上传；复制后由用户自行决定分享。

新设备适配流程：先用 observe 构建采集能力，核对符号与失败项；正式适配通过回归与真机检查后，
再单独扩大“已验证”列表。报告的 `matches-tested-Find-N5-profile` 表示匹配已测画像，
不会把一次符号检查说成该用户手机已完成所有功能验收。
